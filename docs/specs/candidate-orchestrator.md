# Spec: run one candidate through every gate

- Status: Implemented
- Author: Ad Astra Computing Inc
- Date: 7 September 2026
- Related ADRs: none

## Problem

The pipeline works, and every one of its steps is a separate command. Taking wget
CVE-2026-16599 from a screen entry to a signed review PR took twelve invocations
by hand, each with its own flags, in an order that matters: a no-spend gate has to
run before the paid step it protects, and a paid step's output has to be
re-checked before the next paid step. An operator remembers the order. An
unattended run does not, and the month of autonomous operation Jason wants cannot
depend on someone typing the steps in the right sequence.

## Goals

- One command takes a screened candidate to the point where a cert can be
  dispatched, with every gate enforced in order and the run stopping at the first
  refusal.
- The run leaves a record of which steps ran, which gate stopped it and why, so
  a fresh context can resume rather than start over.
- Model spend happens only after every free check ahead of it has passed.
- Nothing the orchestrator does is new. It sequences the existing commands and
  their existing refusals.

## Non-goals

- Dispatching the cert, signing or opening the PR. Those cross into CI and the
  public fork and stay operator-triggered for now, with the orchestrator handing
  over a bundle that `bundle probe --check` accepts.
- Retrying a failed model step with a different prompt or model. A failed gate
  is a result, not a fault to route around.
- Choosing candidates. The screen and its precision gates do that.

## Design

`trace candidate run --inbox-entry DIR --nixpkgs-checkout DIR --nixpkgs-rev REV
--out DIR [--patcher-model M] [--reviewer-model M] [--reproducer-model M]`

Steps, in order, each with the refusal that stops the run:

1. `bundle bootstrap`: no fix commit, no package path, version drift.
2. `bundle assemble` and `bundle finalize`: schema failure.
3. fetch the pinned source (`nix build <rev>#<attr>.src`, extracted to a
   scratch directory) and `bundle preflight`: does not apply, or already applied,
   which is reported as "not vulnerable" and retires the candidate.
4. Patcher, then `bundle preflight --patch-diff` on the model's payload.
5. Reviewer; a reject verdict stops the run.
6. Reproducer.
7. `bundle probe`; a red probe stops the run.
8. `bundle finalize` with the original `--created-at`.

Every step's stdout and exit code is appended to `<out>/run.jsonl`, one JSON
object per step with a UTC timestamp, so the record is append-only and greppable.
The final line names the gate that stopped the run or `ready-for-cert`.

Resumption: `--resume` skips steps whose outputs already exist and whose
recorded inputs are unchanged, using the same sha binding the probe uses. A
Patcher output is never regenerated by resume; that is a deliberate re-run.

Model spend is bounded by construction: steps 4 to 6 are the only paid ones and
each sits behind at least one free gate that has to pass first. The run prints
the estimated and actual cost from the invocation sidecars at the end.

Alternatives rejected: a shell script (no structured record, no resume, and the
refusals become exit-code arithmetic); putting the sequencing into `replay
--execute` (that command is one role at a time by design, and the gates are not
roles).

## Acceptance criteria

- [ ] A candidate whose upstream patch does not apply stops at step 3 with no
      model invocation recorded.
- [ ] A candidate whose pinned source already carries the fix stops at step 3 and
      is reported as not vulnerable.
- [ ] A Reviewer reject stops the run before the Reproducer is called.
- [ ] A red probe stops the run before finalize and the record names the arm that
      failed.
- [ ] A complete run ends with `bundle probe --check` passing on the output.
- [ ] `--resume` on a completed run performs no model call.
- [ ] `run.jsonl` has one entry per step attempted, in order, and nothing else.
- [ ] Each model step is driven through the injected adapter in tests, so the
      suite spends nothing.

## Risks and open questions

The pinned-source fetch needs network and a Nix store; on a host without either
the run stops at step 3 with an infrastructure error, which must not be recorded
as a base mismatch. Whether the orchestrator should also dispatch the cert once
the workflow gate has proven itself is a later decision.
