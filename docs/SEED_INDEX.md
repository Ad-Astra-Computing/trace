# Seed Index

The thirteen real-CVE bundles under `traces/example/CVE-*/` each demonstrate a distinct shape in the v0 contract. This document is the single-page external-review map: what each bundle is for, what it proves, what it does *not* prove, and where to look first if you're auditing the corpus.

The synthetic `CVE-0000-*` fixtures are not catalogued here; they exist to exercise specific Steward rules and per-document schema edges, and are read against `expect.json` notes individually.

## Per-bundle detail

### `CVE-2024-13978--libtiff` · auto-merge · deterministic-no-model

libtiff `fax2ps` null-pointer dereference under `TIFFTAG_FAXFILLFUNC`. The bundle ships the upstream-attached crash TIFF (`repro/crash_poc.tif`, 9556 bytes, gitlab issue #649) and a reproducer that synthesises an unpatched libtiff via `overrideAttrs (old: { patches = filter (p: !match "CVE-2024-13978.*" p.name) old.patches; })` and runs `fax2ps` against the PoC. The discriminating signal is SIGSEGV on unpatched, exit-1 on patched.

* **What's load-bearing**: `patch.diff` is byte-equivalent to the nixpkgs backport at `372f8113f50783002c77f1490aae98ce888608d2` (PR [#436742](https://github.com/NixOS/nixpkgs/pull/436742)). Two upstream fix commits, both libtiff-master, both upstream-signed. The PoC is the same artifact upstream attached to its own bug tracker.
* **What's pre-baked**: `patch-rationale.md`, `review.md`, `reproducer-log.txt`, `build.json`, the scoring reports. None of those came out of a model invocation; each carries an explicit "not produced by a model invocation" provenance preface. CI Builder overwrites `build.json` at dispatch time.
* **Notable property**: this bundle is the v0 Hydra-graduation criterion *concrete*. Run [25077946199](https://github.com/Ad-Astra-Computing/trace/actions/runs/25077946199) timed out on `patched_build`, producing a clean rule-8 deny with skip-sign. The architecture worked: no false signature, no time-budget-bypass shortcuts, the deny is the milestone. See [DECISIONS.md](DECISIONS.md) entry "libtiff CVE-2024-13978 dispatch".

### `CVE-2024-49195--mbedtls` · auto-merge · model-attested

mbedtls patch-release case. The historical nixpkgs fix at `bd4bd87293ad` is exactly 2+2 lines: version bump and matching `src.hash`. No `vendorHash`, no `cargoHash`, no `npmDepsHash`.

* **Pedagogical role**: cleanest test case for the hash-verifiability scorer (rule-8 generalization). Only one hash slot to verify, no transitive package changes, no maintainer-driven ride-along scope. Either the Patcher refuses with "rule 8: no grounded hash for this slot," or it emits the prefetched hash byte-equal to the upstream-derived value. There is nowhere for a hallucinated hash to hide.

### `CVE-2025-13878--bind` · auto-merge · model-attested

ISC bind 9.20.17 → 9.20.18 patch-release on a 178-line `package.nix`. The historical nixpkgs fix (`6bd98c02c5f7`) is again exactly 2+2 lines: version + `src.hash`. Empty intersection with maintainer-driven changes.

* **Pedagogical role**: tests Patcher's discipline on a large existing package definition. The CVE-driven minimum diff is 2+2 lines; Patcher must not generate a "while we're here" cleanup pass. Reproducer correctly refuses (network DNS daemon → no sandbox-positive reproducer feasible), Steward correctly denies on rule-7 with skip-sign. See run [25074542863](https://github.com/Ad-Astra-Computing/trace/actions/runs/25074542863).
* **Notable property**: pairs with the libtiff bundle as a "deny-honestly" demonstration on the auto-merge path: bind for "no reproducer can be built for this CVE class," libtiff for "Builder cannot fit this bundle in 30 minutes." Two distinct deny shapes, both reach skip-sign cleanly.

### `CVE-2025-4598--systemd` · human-review-required · model-attested

systemd-coredump signal-handler race (CWE-364, CVSS 4.7). Patch is canonical clean patch-release: version bump 257.5 → 257.6 with `src.hash` update. No `vendorHash` (systemd is not Go), no transitive package changes.

* **Pedagogical role**: `human-review-required` route via `kind_reason = blast-radius-exceeds-threshold`. systemd is foundational; reverse-closure count exceeds the v0-default threshold of 500 by a wide margin. Even when the patch itself is clean, operational risk on a bottom-of-the-stack package crosses the human-review line. The bundle proves the threshold gate fires on real, low-CVSS, structurally-clean changes when *operational* risk dominates.

### `CVE-2025-67899--uriparser` · human-review-required · model-attested

uriparser 0.9.9 → 1.0.0 (project's first stable major release). Unbounded-recursion / stack-consumption (CWE-674) via `ParseMustBeSegmentNzNc` with comma-heavy input. **Retired as v0.1 sandbox-positive anchor under F11** (DECISIONS 2026-05-19 (latest)).

* **Pedagogical role**: codifies criterion 6 (`shipped-binary-non-discrimination`) on the sandbox-PoC suitability filter. The bug exists in the source — diagnostic build with `NIX_CFLAGS_COMPILE='-O0 -fno-optimize-sibling-calls'` and `hardeningDisable=['all']` segfaults on the upstream PoC (8600 comma-separated 1-byte path segments) under a 1 MiB thread stack. But at nixpkgs default optimization (gcc -O2 + hardening), gcc tail-call / sibling-call optimization elides the recursion at compile time. `uriParseUriA` returns URI_SUCCESS cleanly. trace's v0.1 evidence claim is about the binary nixpkgs actually ships, not source-level truth — so this CVE class is out of v0.1 anchor scope.
* **Per-bundle iteration history (this slice)**: Reproducer (sonnet-4-5) wrote a v4-clean reproducer.nix using the public PoC from upstream issue #282 (a C harness calling `uriParseUriA` on the long-comma URI). Three small per-bundle fixes were applied: (1) C harness API call shape — `uriParseUriA(&state, uri_str)` not `uriParseUriA(&uri, uri_str)`; (2) `LD_LIBRARY_PATH` was unbound under `set -u`; (3) fixture comma count needed to match the actual upstream PoC count (~8600, not ~600). Then the optimization-masking finding terminated the slice — within CLAUDE.md's 3–4 per-bundle fix soft cap. Stopping at the optimization-masking finding (a CVE-class issue, not a runnability fix) is the principled call.
* **Reproducer honesty (F11 vindicates the contract)**: at -O2 the unpatched side emitted `PREDICATE FAILED: unpatched uriparser did not crash as expected` and refused to mint SIGNAL_UNPATCHED. Same shape as wget2's F6 retirement: the contract layer refused to fake a green signal on a candidate whose CVE-class doesn't fit the v0.1 sandbox-positive contract.
* **Reviewer hallucination N=3 (different shape)**: this run's Reviewer reported `reviewer_family: anthropic-claude` (should be `anthropic-sonnet`) so `rule_honored: false`. N=3 hallucination class (git-lfs + django reported `openai-gpt`; this one reported the wrong family-name for itself). N=1 correct (assimp). Executor-side cross-family enforcement is independent of self-reported attestation, so this is a Reviewer-prompt accuracy nit, not a contract violation.
* **Prior-archive provenance**: the first run for this bundle (preserved under [`_first-run-archive/`](../traces/example/CVE-2025-67899--uriparser/_first-run-archive)) surfaced a contract bug in v0 Patcher: `github-release-archive` confidence + `nix-prefetch-url` against `fetchFromGitHub` produces a hash divergent from what `fetchFromGitHub` actually demands. The current bundle's Patcher output is byte-identical to the historical nixpkgs fix at `e9da914af2cd`. That archive is intentional; deleting it would erase the evidence that the pipeline was wrong before it was right.
* **Cert dispatch SKIPPED**: the reproducer would honestly PREDICATE FAILED on the unpatched side (already verified via local probe). No need to spend a CI cycle to re-prove that.

* **Pedagogical role**: `cross-family-pair-unavailable` route. Deterministic-no-model means no model pair, so by definition no cross-family pair to enforce. * **Why no reproducer**: heap-buffer-overflow at `scope_new` is silent on a non-ASAN build. `reproducer-refusal.json` declares rule 3 with the principled reason; the 18-byte PoC ships at `repro/mruby_crash.txt` for a v1 Reproducer that runs against an ASAN-aware Builder profile. PoC is real (OSV CVE-2025-7207 references[] type=EVIDENCE).
* **Upstream provenance**: fix commit `1fdd96104180...` is GPG-signed by Yukihiro "Matz" Matsumoto personally (verified via GitHub API `verification.verified = true`). nixpkgs precedent at `4d9e5f64b7a7` (PR [#450791](https://github.com/NixOS/nixpkgs/pull/450791), 2025-10-10).

### `CVE-2025-13151--libtasn1` · human-review-required · model-attested

GNU libtasn1 stack-based buffer overflow in `asn1_expand_octet_string` (CWE-787, CVSS 7.5). First candidate selected through the v0.4.0 sandbox-positive PoC suitability filter — and the second model-attested anchor attempt to be retired through learning what the filter missed.

* **Pedagogical role**: `poc-construction-exceeds-anchor-depth` route — F8 (DECISIONS 2026-05-17 post-close). The candidate passed criteria 1–3 (local-file PoC, no network, no daemon) cleanly. Patcher (opus-4-7) emitted a byte-clean 4.20.0 → 4.21.0 version+hash bump matching nixpkgs master. Reviewer (sonnet-4-5) accepted across families. Reproducer (sonnet-4-5) produced structurally-valid `reproducer.nix` with per-side `passthru.test` (F2), gated SIGNAL emission (F3), and the hash-pinned FOD carve-out for unpatched-src.
* **Why retired**: The model invoked `${unpatched}/bin/asn1Parser -c evil.der`, but `asn1Parser` parses ASN.1 DEFINITIONS files (.asn syntax), not DER-encoded data. Correct tool is `asn1Decoding`, which decodes DER given a definition schema + encoded blob. Triggering the actual bug (a 1-byte off-by-one stack overflow at `lib/decoding.c:1986` in `asn1_expand_octet_string`) requires constructing both a matching schema and a DER blob that walks the decoder to the specific name-stitching call site. Local probe (`asn1Parser -c evil.der` → rc=1 "syntax error") confirmed the predicate wouldn't fire; F3's gating contract would exit `PREDICATE FAILED` honestly without minting a SIGNAL. Cert dispatch was skipped — local proof was sufficient and burning Linux cert cycles would replicate the conclusion without new information.
* **What it taught**: F8 added a fourth criterion to the sandbox-positive filter — *PoC construction depth ≤ model-attestation-budget*. Surface CVE descriptions of the form "stack overflow in `<function>` on malformed input" don't predict whether a sonnet-class model can construct a fixture that fires the bug from the description alone. Candidates whose exploitation requires authoring a parser schema, a protocol handshake, or matching a hard-to-discover internal code path are now filtered out at harvest time.
* **Sidebar**: while verifying the next backup candidate (micropython CVE-2026-1998), OSV confirmed v1.27.0 is `last_affected` not `fixed` — the fix lives in an open PR (#18671) against a contributor fork. `eval/candidates.jsonl` asserts the opposite; the candidate row is flagged for reharvesting.

### `CVE-2025-26625--git-lfs` · auto-merge · model-attested

git-lfs symlink/hardlink-following arbitrary file write (CWE-59, CVSS 7.3). **First model-attested + sandbox-positive + Linux-cert-green auto-merge bundle in the corpus** (cert run [26075978701](https://github.com/Ad-Astra-Computing/trace/actions/runs/26075978701), 2026-05-19). The slice that closed it drove three Linux-sandbox-portability lessons (F9 / F9b / F9c) which are now codified in Reproducer prompt v4.

* **Pedagogical role**: the *positive* case for the sandbox-PoC suitability filter, after two retirement cases (wget2 / F6, libtasn1 / F8) taught what to filter out. The CVE summary directly describes the PoC shape ("git lfs checkout writes through symlinks"), the affected binary's docs are well-known to a sonnet-class model, and there is no protocol-internal fixture-engineering step. The fix tier is patch-release version bump with `vendorHash` unchanged — Patcher's simplest shape. The reproducer fixture is a `pkgs.writeText` LFS pointer + a working-tree symlink + a single `git lfs checkout` invocation, all local-filesystem, all reachable in one Reproducer iteration.
* **Patcher provenance**: opus-4-7 produced a byte-clean 3.7.0 → 3.7.1 version+hash bump matching the historical nixpkgs fix at commit `e839548206c9`. `vendorHash` is preserved across the bump (no go.mod changes in the security fix); Patcher correctly left it unchanged.
* **Cert path (four runs)**:
  * Cert [25994775455](https://github.com/Ad-Astra-Computing/trace/actions/runs/25994775455) — F9: `HOME=/homeless-shelter` so `git lfs install` cannot write the global gitconfig filter entries. Fix: `export HOME=$TMPDIR` (commit `87cde02`).
  * Cert [26071945288](https://github.com/Ad-Astra-Computing/trace/actions/runs/26071945288) — F9b: `2>run.err` captures stderr only; git-lfs writes `Checking out LFS objects: 100%` to stdout which the fallback predicate needs. Fix: `>run.err 2>&1` (commit `d60297f`).
  * Cert [26072115636](https://github.com/Ad-Astra-Computing/trace/actions/runs/26072115636) — F9c: fallback branch fired with substring `silently-refused-symlink-write...` while reproducer-log.txt declared the primary-branch substring `rejected-symlink-write...`. Fix: extend primary regex to include `not a regular file` (the real git-lfs 3.7.1 diagnostic) so the primary branch fires with the declared substring (commit `026596c`).
  * Cert [26075978701](https://github.com/Ad-Astra-Computing/trace/actions/runs/26075978701) — green end-to-end. Builder ✓, build.json shape ✓, SIGNAL substrings present ✓, Steward allow ✓.
* **Empirical predicate (Linux x86_64, cert #4)**: unpatched 3.7.0 follows the symlink and creates `/tmp/owned-by-cve-2025-26625` (empty file matching size=0 LFS pointer); patched 3.7.1 refuses with `Checkout error for "lfs-tracked-file": not a regular file: "lfs-tracked-file"` and rc=0.
* **What this proves at the contract layer**: the v0.4.0 sandbox-PoC suitability filter has its first positive evidence — a candidate that passed criteria 1–4 actually clears the chain end-to-end on Linux. The four-cert iteration history is itself proof that the cert loop is the right place to surface Linux-portability gaps; each of F9/F9b/F9c was a real lesson the F8 filter could not have predicted at harvest time. Reproducer prompt v4 now ships those lessons so future bundles authored under the v4 contract should not repeat them.
* **Reviewer model-attestation nit (still open)**: claude-sonnet-4-5 reported `patcher_family_observed: openai-gpt` while the Patcher was anthropic-claude (opus). The cross-family rule was claimed honored on a hallucinated counterparty. The executor enforces cross-family pairing independently; the bundle's correctness does not depend on this attestation. Tracking as a Reviewer-prompt accuracy issue worth its own slice when the Reviewer corpus is large enough to scope prevalence.

### `CVE-2025-59681--django` · human-review-required · model-attested

Django QuerySet column-alias SQL injection on MySQL/MariaDB (CWE-89, CVSS 8.7). First candidate retired as **F10 — `poc-needs-validation-bypass-fixture`** (DECISIONS 2026-05-19). Passed F8 criteria 1–4 and the codex-peer-agreed F8-extension shape for generated-SQL PoC (compiler/query-generation CVEs assert on compiled output rather than runtime execution).

* **Pedagogical role**: first concrete data point on the **validation-bypass** failure class. F8 (libtasn1) was about model lacking the deep knowledge to construct a fixture at all. F10 (django) is different: the model has plenty of knowledge to construct A fixture — but the NAIVE fixture hits a pre-existing validation in the unpatched version, not the strengthened validation the CVE fix targets. Both unpatched and patched reject the model's first-shot fixture; the discriminating predicate doesn't fire.
* **Chain provenance**: Patcher (opus-4-7) produced a byte-clean `4.2.24 → 4.2.25` version+hash bump matching nixpkgs commit `12db2344c7d6`. Reviewer (sonnet-4-5) accept with cited evidence (same `patcher_family_observed: openai-gpt` hallucination as git-lfs). Reproducer (sonnet-4-5) ran against the newly-wired v4 prompt and applied the generated-SQL PoC shape correctly (real MySQL backend ENGINE, HOME export, v4 capture, same-substring rule). The bundle's `reproducer.nix` correctly names `'django.db.backends.mysql'` as the test backend ENGINE — the F8-extension's load-bearing instruction worked.
* **Four v5-grade Reproducer-prompt findings (raw model output required 4 manual fixes before the test could even run, each is a real pattern worth a worked example)**:
  1. Python `'PASSWORD': ''` inside a Nix `''` multi-line string ends the Nix string. Use `""` or escape `''` → `'''`.
  2. `PYTHONPATH=${unpatched}/${pkgs.python3.sitePackages}` misses propagated runtime deps (asgiref, sqlparse). Build a python env via `pkgs.python3.withPackages (ps: [ ps.django_4 ... ])`.
  3. `INSTALLED_APPS=['testapp']` triggers `apps.populate()` which `import_module('testapp')` fails. Use `INSTALLED_APPS=[]` + `class Meta: app_label = 'testapp'`.
  4. MySQL backend imports `MySQLdb` at module load. Without `ps.mysqlclient` in the env, `django.setup()` errors. For backend-specific CVEs, name the driver as a python env dep.
* **The terminal F10 finding**: even after the four runnability fixes land, the unpatched 4.2.24 raises `ValueError: Column aliases cannot contain whitespace characters, quotation marks, semicolons, or SQL comments.` That's a PRE-EXISTING validation in 4.2.24. The CVE-2025-59681 fix STRENGTHENS this on the MySQL identifier-quoting path specifically; a naive backtick-and-semicolon alias hits the older check, not the new one. Discovering the right bypass shape (an alias that passes the existing whitespace/quote/semicolon check but still triggers MySQL's backtick-injection) requires reading the fix's diff and understanding the framework's existing validation surface — beyond the model-attestation budget.
* **Preserved as evidence**: the bundle's `reproducer.nix` carries the four manual edits inline (with comments naming each) so future readers can see what v5-grade prompt expansion would prevent. The terminal F10 outcome — `ValueError: Column aliases cannot contain ...` raised on the unpatched side — is the proof that this CVE class is out of v0.1 anchor scope without bypass-shape knowledge. Future v0.2 work may pick django back up as a `validation-bypass benchmark` candidate.

### `CVE-2025-69194--wget2` · human-review-required · model-attested

GNU wget2 Metalink path-traversal (CVSS 9.8 CWE-22). The bundle drove the F1–F7 contract slice across six cert dispatches (2026-05-13 → 2026-05-17), surfacing seven distinct structural findings in the framework. Six were closed at the contract layer with empirical proof; F6 (the wget2-PoC-needs-network shape) triggered retirement as v0.1 anchor.

* **Pedagogical role**: `sandbox-poc-requires-network` route. The retirement is itself the demonstration: the framework refused to mint a green signal on a reproducer that didn't actually exercise the CVE. F3's predicate-gating contract held; cert 6 ([25982588546](https://github.com/Ad-Astra-Computing/trace/actions/runs/25982588546)) shows both reproducer-side derivations built clean, both wget2 binaries ran honestly, both exited `PREDICATE FAILED` with no SIGNAL minted.
* **What it proves at the contract layer**: F1 (Patcher drop-only relaxation for obsoleted nixpkgs-side patches), F2 (per-side `passthru.test`), F3 (gated SIGNAL emission), F4 (Builder pkgs-pin to bundle's nixpkgs), F5 (`--force-metalink -i` CLI), F7 (pre/post-patch tree separation). See DECISIONS 2026-05-13 → 2026-05-17 for the full arc.
* **Why retired**: wget2's metalink CVE class requires a fetchable URL to trigger the path-traversal write. wget2 rejects `file://` / `data:` schemes; the Nix build sandbox is network-isolated. Bridging this gap would require either spawning a local HTTP responder inside the test (overfitting the framework to wget2's shape) or replacing the filesystem-based predicate with parser-side observation (overfitting to wget2's debug output). Neither belongs in v0.1 generic scaffolding. The corpus's anchor-selection filter (DECISIONS 2026-05-17 close, `docs/CORPUS.md` § Sandbox-positive PoC suitability filter) was codified to prevent this CVE class from being selected as a future v0.1 anchor.
* **Preserved artifacts**: F1's `patch-drop-rationale.md`, F7-correct `reproducer.nix` shape, six `_*-run-archive/` directories documenting the slice arc, and the final post-patch-drop `patch.diff` are reference material for future contract work.
